# CLAUDE.md — PocketRemote

The full spec is in `PLAN.md`. Read it before starting any task, and follow its phases in order.

## Non-negotiable rules

- **Security first.** Everything marked MUST in `PLAN.md` §3 is binding. Never weaken a limit, skip a check, remove a test, or add a command type to make a task easier. If a task seems to need that, stop and ask.
- **No home-made crypto protocols.** Use Noise (`snow` in Rust; the `app/src/noise/` implementation in TS, verified by test vectors). Never change the cryptography without asking first.
- **Never log** keys, pairing tokens, decrypted payloads or typed text.
- **Never add** commands for shell, files, URLs, clipboard or arbitrary key combos.
- **Nothing paid.** Do not add services, accounts or dependencies that cost money.
- **One phone.** Exactly one paired phone; pairing a new one revokes the old.
- **Android only for 1.0.** Do not build a web client or any iOS-specific code (see `PLAN.md` Appendix A).
- **Expo Go stays runnable** in development: no dependency that needs `expo prebuild`. Config plugins are fine. Keep `app/src/noise/`, `session.ts` and `protocol.ts` free of React Native imports.
- **Protocol changes start in `desktop/src/protocol.rs`.** Regenerate `app/src/protocol.ts` and update `protocol/fixtures/`. Never hand-edit the generated file.
- **Security-sensitive files** need the human's review: `noise.rs`, `pairing.rs`, `keystore.rs`, `net.rs`, `server.rs`, `app/src/noise/**`, `app/src/session.ts`. Say in the PR description what changed in them and why.
- **New dependencies:** justify each one in the PR. Check its current docs. Prefer fewer.
- **Check, don't guess:** crate and package APIs change. Look at current docs before using one. If the docs differ from `PLAN.md`, follow the docs and note it in the PR.

## Checks after every edit (all must pass)

Desktop:
```sh
cd desktop
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cargo deny check
```

App:
```sh
cd app
npx tsc --noEmit
npx eslint .
npx jest
```

Protocol sync (after any change to `protocol.rs`):
```sh
# regenerate, then confirm no diff
git diff --exit-code app/src/protocol.ts
```

Before a release: `npx expo-doctor`, `npm audit --omit=dev --audit-level=high`, and the full CI matrix green.

## When to stop and ask

- At every **ASK** marker in `PLAN.md`.
- At the end of Phase 0 (spike report) and before tagging `v1.0.0`.
- When a check fails and fixing it would mean changing a MUST.
- Before deleting or renaming anything under `protocol/`.

## Scope of instruction files

`app/AGENTS.md` (generated by create-expo-app) gives Expo-specific context only. If it conflicts with this file or `PLAN.md`, this file and `PLAN.md` win.
